# Data Formats and Schemas

## In-memory schemas (`masgym.data.schemas`)
- **`Agent`**: `agent_id:int`, `role:Role{orchestrator,worker,tool_executor,memory}`,
  `backbone:str`, `permitted_tools:tuple[str]`, `can_write_memory:bool`, `group:str`.
- **`Topology`**: `name:{star,chain,tree,mesh}`, `n_agents:int`, directed `edges:tuple[(src,dst)]`,
  `branching_factor:int`. Node `0` is the orchestrator (hub/root).
- **`AdversaryConfig`** (Eq. 2): `beta:float[0,1]`, `colluding:bool`, `adaptive:bool`,
  `orchestrator_compromised:bool`, `malicious_tools:bool`, `sybils:int>=0`, `poisoned_memory:bool`.
- **`EnvConfig`**: `n_agents`, `topology`, `horizon`, `forced_degree(k)`, `branching_factor`,
  `propagation{independent_cascade,threshold}`, `p_infect`, `threshold(theta)`, `orchestrator_id`,
  plus synthetic-agent params `base_unsafe_action_prob`, `benign_success_base`.
- **`TraceStep`**: `t`, `compromised:frozenset[int]`, `recorded_transitions:tuple[str]`
  (e.g. `"unsafe_action:agent3"`, `"exfiltration:agent5"`, `"sabotage:coordination"`),
  `messages:tuple[str]` (NOT read by the checker).
- **`Trace`**: `steps`, `n_agents`, `seed_set(B_0)`, `witness_completed`, `detected_step`, `recovered`.
- **`Episode`**: `env`, `adversary`, `trace`, `phi`, `psi`, `tokens`, `latency`, `human_intervention`.

A tiny serialized example is in `examples/synthetic_data/example_episodes.json` (synthetic).

## Real benchmark data (external; provisioned manually on EC2)
The paper uses real benign task pools as agent workloads. None is downloaded by this repo.
`masgym.data.adapters.BenchmarkTaskAdapter(name, root)` reads already-provisioned files.

Expected layout (set `data.root` in the config to the dataset directory):

```
<data.root>/
  <benchmark>/            # agentbench | gaia | webarena | swebench | mmlu | gsm8k
    tasks.jsonl           # one task per line
    splits.json           # {"calibration": [...ids], "test": [...ids]}   (optional)
```

Minimum required columns/fields per task record (JSONL):
- `task_id:str` — unique id
- `prompt:str` — the benign user goal (decomposable across roles)
- `tools:list[str]` — tool names the task may use
- `k_forced:int` — forced-coordination degree (>=2 recommended)
- `success_spec:object` — machine-checkable success predicate spec (maps to `Psi`)
- `security_spec:object` — machine-checkable compromise predicate spec (maps to `Phi`)
- `group:str` (optional) — for group-conditional metrics (e.g., difficulty/repo)

### Provisioning notes (manual; may require registration / license)
- **AgentBench, GAIA, WebArena, SWE-bench**: download from their official releases; some require
  accepting terms or GitHub access. Place under `<data.root>/<benchmark>/`.
- **MMLU, GSM8K**: public; used only for worker subtasks.
- Real **tool emulation** (ToolEmu) and **LLM backbones** require API keys / model weights (see
  `docs/ec2_experiment_guide.md`). This repo never bundles or downloads them.

Any dataset requiring manual download, authentication, or license approval is also recorded in
`audits/implementation_gaps.md` and `TODO_IMPLEMENTATION.md`.

## Output formats (generated by scripts, never hard-coded)
- `sweep_metrics.csv` — one row per configuration with `AdversaryConfig` fields + `SystemMetrics`.
- `ablation.csv` / `ablation_summary.json` — collusion, orchestrator, evaluator-integrity.
- `theory_check.json` — Monte-Carlo vs closed-form verification.
- `corb_trajectory.csv` / `corb_pareto.json` — the CoRB loop trajectory and Pareto frontier.
- Every file includes a provenance header with `synthetic: true|false`.
